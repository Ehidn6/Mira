# Mira

Нативная экспериментальная MiraOS, графовый язык и его bootstrap-компилятор. Основной проект — `projects/MiraOS`. Отдельная Linux IDE удалена; среда разработки развивается внутри MiraOS.

- `./launch-miraos.sh` — загрузить MiraOS в QEMU с USB-клавиатурой. Готовый образ используется повторно; изменения исходников вызывают пересборку.
- `./run-miraos.sh --build` — принудительно пересобрать образ без запуска.
- `./install-miraos-desktop.sh` — установить пункты запуска, справки и экспорта в меню приложений.
- `./launch-miraos.sh --context` — открыть актуальный `MIRA_CONTEXT.md`.
- `./launch-miraos.sh --export` — извлечь исходник, сохранённый внутри MiraOS.
- `cargo build -p mira-lang` — собрать компилятор и точечные инструменты работы с исходниками.

Внутри MiraOS: **Alt+X → source compile / source run** компилирует выбранную функцию вместе с нужными соседними определениями и пробно запускает результат без замены работающего ядра. Входная функция без параметров, результат i64/f32/bool/unit; ограничения и порядок работы описаны в `MIRA_CONTEXT.md`. Ctrl+S сохраняет исходник отдельно от компиляции.

Начало работы для помощника: `AGENTS.md`. Синтаксис и проверяемые примеры: `language/README.md`. Фактическое состояние, управление, ограничения и долгосрочный замысел: `MIRA_CONTEXT.md`. Не читать весь проект заранее.

Граф задаёт экземпляры, связи и вложенные Z-пространства; внутри ячеек остаётся текстовый код. Исходный projects/MiraOS — рекурсивный контейнер: содержимое объектов и их дети хранятся вместе, согласно областям определений и Z. Для просмотра используйте `target/release/mira source projects/MiraOS enter NAME/PATH`; не читайте весь контейнер ради одного объекта. Отдельных частей/index и произвольной группировки нет. Linux пока нужен для bootstrap-сборки и QEMU; сам нативный образ не использует Linux runtime. Загрузка на физическом компьютере, сеть/ChatGPT и полная самокомпиляция ещё не готовы.
